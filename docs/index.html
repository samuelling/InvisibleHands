Start here

Two minutes. What the pieces are, and which path to take.

There are three pieces. Apps (yours, and other people’s). A room: a code like moss-kiln-opal-fern-42 that apps use to find each other. And the relay: a small server on the internet that passes messages around inside each room. You never run the relay unless you want to; one is already running at wss://invisible-hands.samuelling.workers.dev.

An app can be a destination (it has knobs others can turn), a source (it turns other apps’ knobs), or both. Every knob is a number from 0 to 1. Apps can also publish outputs (their own wiggles, also 0 to 1) for others to plug in.

With Claude

For people who build with Claude (claude.ai, the desktop app, or Claude Code).

  1. Download the instructions

    Get INVISIBLE_HANDS.md. It’s written for Claude: what the protocol is, what to expose and what not to, how to map knobs, timing, testing, and what to tell you at the end.

  2. Put it where Claude can see it

    In Claude Code: drop it in your project folder. In the Claude app: attach it to the chat, or add it to your project’s files.

  3. Say one sentence
    Read INVISIBLE_HANDS.md and add Invisible Hands to this app.

    If you have a key already, add it: “My key is ih_…”. If you know which knobs you want, say so. Otherwise Claude suggests a list and asks.

  4. Test with the link it gives you

    Claude finishes with two links: your app with ?room=…, and the console in the same room. Open both. Drag a slider in the console and your app should move.

  5. Ask for a key, paste it in

    When it works, ask for a key, then tell Claude: “Use the key ih_…”.

A web app that can be moved

For a web page with things worth turning. About fifteen minutes.

  1. Add the file

    One script, no dependencies. Link it, or better, download it next to your other scripts so your app never depends on our address:

    <script src="https://samuelling.github.io/InvisibleHands/invisible-hands.js"></script>

    In a module-based app: import './invisible-hands.js'; and then use globalThis.InvisibleHands.

  2. Pick your knobs

    Write down 4 to 20 things a stranger could enjoy turning: speeds, sizes, colours, densities, random seeds, on/off switches, a button that fires something. Leave out anything that deletes, saves, buys, records, navigates away, or flashes the screen fast.

    Give each one an id that never changes (spatialFreq), a label people read (Spatial frequency), and a kind: cont for a dial, toggle for a switch, trig for a button.

  3. Turn each into a number from 0 to 1

    Write a get that says where it is now (0 to 1) and a set that puts it somewhere. They must be exact opposites. Recipes are below.

  4. Create the hands, once 
    const hands = InvisibleHands.create({
  app: 'my-app',               // a short name for this kind of app
  name: 'My App',              // what people see
  key: 'ih_…',                 // your key (step 7); leave out while testing locally
  params: [
    { id: 'speed', label: 'Speed',
      get: () => Math.log(state.speed / 0.1) / Math.log(100),
      set: v => { state.speed = 0.1 * Math.pow(100, v); } },
    { id: 'trails', label: 'Trails', kind: 'toggle',
      get: () => state.trails ? 1 : 0, set: v => { state.trails = v > 0.5; } },
    { id: 'burst', label: 'Burst', kind: 'trig',
      get: () => 0, set: v => { if (v > 0.5) fireBurst(); } }
  ]
});

    Keep set cheap: store the number and let your drawing or audio loop use it. It can be called 25 times a second. For audio, glide instead of jumping: param.setTargetAtTime(x, ctx.currentTime, 0.015).

  5. Add the panel 
    document.querySelector('#settings').append(hands.panel());

    The panel has Start a room, a box to type a code, Copy invite link, Leave, and the Let others move my controls switch. It takes your page’s font and colours. Put it in your settings, or behind a small “Hands” button.

    If your app has its own slider for a knob, call hands.recenter('speed') when the person drags it, so a running swing follows their hand.

  6. Test it

    Follow Testing without a key. Open your app and the console in the same room; every knob should move your app, and your own sliders should follow.

  7. Get a key

    See Getting a key. Paste it into create({ key }). A website key is tied to your site’s address, so it’s fine in the page’s code.

  8. Ship it

    Share invite links: your app’s address plus ?room= and a code. A page opened that way joins the room by itself. The panel’s Copy invite link makes one for you.

Turning knobs into 0..1

// a straight range, lo..hi
const lin   = (v, lo, hi) => lo + v * (hi - lo),        unlin   = (x, lo, hi) => (x - lo) / (hi - lo);
// anything heard or seen in ratios: Hz, seconds, zoom (lo must be above 0)
const expo  = (v, lo, hi) => lo * Math.pow(hi / lo, v), unexpo  = (x, lo, hi) => Math.log(x / lo) / Math.log(hi / lo);
// one of n choices: a mode, a preset, a menu
const pick  = (v, n) => Math.min(n - 1, Math.floor(v * n)), unpick = (i, n) => (i + 0.5) / n;
// a whole number lo..hi
const count = (v, lo, hi) => Math.round(lin(v, lo, hi));

Example: a filter from 80 Hz to 12 kHz is set: v => filter = expo(v, 80, 12000), get: () => unexpo(filter, 80, 12000).

A web app that moves others

For LFOs, sequencers, sensors, mod matrices: things that do the turning.

  1. Create hands with no knobs
    const hands = InvisibleHands.create({ app: 'my-lfo', name: 'My LFO', key: 'ih_…' });
hands.join('moss-kiln-opal-fern-42');   // or let a ?room= link join it, or show hands.panel()
  2. Listen for who’s there
    hands.on('peers', peers => {
  // each peer: { id, app, name, params: [{id, label, kind, value}], outs: [{id, label}], state: {} }
  drawMyMatrix(peers);
});

    Show names and labels with textContent, never as HTML. They come from strangers.

  3. Turn things
    hands.set('app:gaborgrove', 'spread', 0.7);                // put it at 0.7
hands.mod('app:gaborgrove', 'spread', 0.3 * Math.sin(ph));  // swing ±0.3 around where its owner left it
hands.mod('app:gaborgrove', 'spread', 0);                   // let go
hands.ramp('app:gaborgrove', 'burst', [[5, 1], [400, 0]], hands.serverNow() + 80);   // an envelope

    The first argument is who: 'app:<name>' for every copy of an app (best for saved patches), a peer’s id for one, or null for everyone.

  4. Use one timer for everything

    Make all of a tick’s moves inside one setInterval (20 to 25 a second is plenty; slow swings look the same at 10). Moves made together leave as a single frame, and repeated values aren’t sent. Each frame costs the relay the same, so this matters.

    For sharp shapes (envelopes, gates, drum hits) send one ramp, never a stream of sets. The far app plays it on its own clock, so it arrives clean. Demo 3 shows why.

  5. Keep going in a background tab, if you need to

    Browsers slow timers in hidden tabs to once a second. If your source must keep playing there, drive it from a Web Worker’s timer (MEGA·CV does this).

Outputs

Let other apps use your app’s wiggles as sources.

  1. List them
    InvisibleHands.create({ …, outs: [{ id: 'level', label: 'Level', get: () => meter.level }] });

    Each returns 0 to 1. The library reads them a few times a second and sends only what changed.

  2. Read other apps’ outputs
    hands.on('state', peer => { useAsModulation(peer.state.level); });
  3. Patch

    Listening to one app’s output and sending it to another app’s knob as a mod is a patch cable. Demo 2 does exactly that.

Python

Desktop tools, scripts, Blender, TouchDesigner, a Raspberry Pi, data feeds.

  1. Get the file and one package
    pip install websockets
curl -O https://samuelling.github.io/InvisibleHands/python/invisible_hands.py
  2. Try it from the command line
    python invisible_hands.py peers  moss-kiln-opal-fern-42                     # who's there
python invisible_hands.py lfo    moss-kiln-opal-fern-42 app:gaborgrove spread --rate 0.3
python invisible_hands.py listen moss-kiln-opal-fern-42                     # everyone's outputs

    Use --relay ws://localhost:8787 while testing locally, or --key ih_… (or INVISIBLE_HANDS_KEY) for the real relay.

  3. Be moved
    import os
from invisible_hands import Hands

state = {'speed': 0.5}
hands = Hands(app='my-tool', name='My Tool', key=os.environ.get('INVISIBLE_HANDS_KEY'))
hands.param('speed', 'Speed', get=lambda: state['speed'], set=lambda v: state.update(speed=v))
hands.out('level', 'Level', get=lambda: 0.3)
print('room:', hands.start())        # a new room; or hands.start('moss-kiln-opal-fern-42')
  4. Move others
    hands.wait_linked()
hands.mod('app:gaborgrove', 'spread', 0.2)
hands.ramp('app:gaborgrove', 'burst', [(5, 1), (400, 0)], at=hands.server_now() + 80)
  5. Pick how it runs

    start() runs in a background thread and calls your set from it. In a single-threaded host (Blender, TouchDesigner, pygame) use start(code, poll=True) and call hands.poll() every frame, so moves happen on your thread. In asyncio, await hands.run(code).

  6. Get a native key

    A program isn’t a website, so it needs a native key. Keep it in an environment variable, never in public code. Ask for one.

Max, Pd, TouchDesigner, Live, SuperCollider (OSC)

Anything that speaks OSC can join through a small bridge.

  1. Install the bridge
    pip install websockets python-osc
curl -O https://samuelling.github.io/InvisibleHands/python/invisible_hands.py
  2. Start it in a room, naming your knobs
    python invisible_hands.py --key ih_… osc moss-kiln-opal-fern-42 --param cutoff --param warp

    It listens for OSC on UDP 9000 and sends to 127.0.0.1:9001 (change with --listen, --host, --port).

  3. Send moves into the room
    Send this OSCto do
    /hands/set/app:gaborgrove/spread 0.7put it at 0.7
    /hands/mod/app:gaborgrove/spread 0.2swing around its owner’s spot (−1..1)
    /hands/ramp/app:gaborgrove/burst 5 1 400 0an envelope: ms, value, ms, value…
  4. Receive moves and outputs
    You getwhen
    /hands/param/cutoff vsomeone moves one of your --param knobs
    /hands/state/<app>/<out> vanother app’s output changes

Any other language

Swift, Kotlin, Go, Rust, C++, Lua: if it can open a WebSocket and read JSON, it can join.

  1. Read the one-page protocol

    SPEC.md has every message. GUIDE.md has a whole conversation written out line by line, a Go example and a Swift sketch.

  2. Connect

    wss://invisible-hands.samuelling.workers.dev/room/<code>?app=<slug>&name=<name>&key=<key>

  3. Say what you have

    On welcome, send {"t":"describe","params":[…],"outs":[…]}. On every join, send it again to the newcomer ("to": "<their id>").

  4. Do what you’re told

    set: clamp to 0..1, apply. mod: clamp to −1..1, apply around where the control stood when the swing began. ramp: play the points on your own clock. Ignore controls you don’t have.

  5. Publish, sparingly

    Send state at most 15 times a second, only for outputs that moved, and everything once when someone joins. Ping three times at the start, then every five minutes.

  6. Take no for an answer

    If the relay closes with 4001, 4003, 4008 or 4029, stop and show the reason it sent. Don’t retry. After 4030 wait a minute. The codes.

Testing without a key

A relay on your own computer: no key, no limits, no internet.

  1. Get the kit

    Download the kit and unzip it, or clone the repository. You need Node 18 or newer.

  2. Start the relay
    cd invisible-hands/relay
npm install
npm run dev                  # → ws://localhost:8787
  3. Point your app and the console at it

    Add ?relay=ws://localhost:8787&room=test-room to your app’s address, and open …/console/?relay=ws://localhost:8787&room=test-room from the kit (serve the folder with python3 -m http.server). Same room, same relay: they find each other.

Getting a key

Once, before your app goes public. Free.

  1. Know what you’ll tell us
    Invisible Hands key, please
App: (its name)
Where it lives: (https://… — the exact website, or "a program" for a native key)
What it moves or listens to: (a sentence)
Roughly how much: (a few people now and then / a performance / always on)
  2. Send it

    With the megaZINE finger-gun form (no account; shoot the right squares, then paste the above), or on the BBS: post in megaZINE Submissions with the title “Invisible Hands key”.

  3. Get it back

    A person reads it and replies with a key (ih_ and 20 letters and digits), by e-mail or BBS mail. Website keys work only from the address you gave. Native keys work from programs: keep those private.

  4. Mind the allowance

    A key gets 2 million frames a month unless we agree on more. A frame is one bundle of moves; the libraries bundle for you. If you hit the ceiling, the relay closes your connections with code 4029 until the 1st. Write to us if you need more.

Apps on the editors’ own sites (samuelling.github.io, crumplabsandbox.github.io, megazine.org) don’t need a key.

Checklist before you ship

  • Every exposed knob moves the app, and the app’s own controls follow.
  • get and set are exact opposites (the console shows the right starting positions).
  • The panel (or your own UI) shows when it’s linked, and the “let others move my controls” switch works at once.
  • Nothing exposed deletes, saves, buys, records, leaves the page, or strobes.
  • Names and labels from other apps are shown as text, not HTML.
  • A source sends from one timer, at most 25 times a second, and uses ramp for sharp shapes.
  • When the console leaves, or the Wi-Fi drops, the app carries on and reconnects.
  • The key is in, and a native key isn’t in public code.

Limits

16 apps a room · 128 knobs and 64 outputs an app · 32 KB a message · 32 points a ramp · labels 64 characters · 240 messages at once, refilling at 120 a second · 30 new connections a minute per address · 2 million frames a month per key.

When it doesn’t work

You seeTry
“This app needs a key”You’re on the real relay from a site that isn’t ours. Test locally or get a key.
“That key is for a different website”The address doesn’t match what the key was issued for (www., http vs https, a different port). Ask us to add the address.
Linked, but the other app isn’t thereCheck both use exactly the same room code and the same relay (?relay=).
Knobs show in the console but don’t move the appThe Let others move my controls switch is off, or set writes somewhere the app doesn’t read.
The console’s sliders start in the wrong placeget isn’t the exact opposite of set.
Envelopes look raggedSend one ramp, not a stream of sets.
Swings snap back when you drag your own sliderCall hands.recenter(id) in the slider’s handler.
It stops when the tab is in the backgroundBrowsers slow hidden tabs. Use a Web Worker timer for sending.

Running your own relay

Optional. For a private installation, a classroom, or no limits but your own.

  1. Get a Cloudflare account

    The relay is a Cloudflare Worker with Durable Objects (the Workers Paid plan).

  2. Deploy
    cd invisible-hands/relay
npm install
npx wrangler login
npx wrangler kv namespace create invisible-hands-keys     # put the id it prints in wrangler.toml
npx wrangler secret put ADMIN_TOKEN                        # a passphrase for issuing keys
npx wrangler deploy

    Change HOUSE_ORIGINS and the ceilings in wrangler.toml to suit you.

  3. Point apps at it

    create({ relay: 'wss://your-relay.workers.dev' }), or ?relay= in any app’s address.
